## Overview

Validating 3D geometry, dialing in physical material parameters (`clearcoat`, `sheen`, `transmission`, `ior`, alpha masks), and preparing lightweight assets for web e-commerce and mobile AR usually forces a slow round-trip into heavy DCC suites like Blender for minor adjustments.

**Mirage** replaces that round-trip with a focused desktop workbench built specifically for glTF 2.0 and real-time WebGL/AR pipelines—combining real-time PBR authoring, metric scale auditing, local asset management, and automated texture/export packaging in a single Electron application.

## Real-Time 3D Workbench & Material Pipeline

The viewport runs on **Three.js** and **@react-three/fiber** with CAD-oriented camera controls, transform gizmos (`translate`, `rotate`, `scale`), HDRI lighting presets plus custom environment uploads, contact shadows, dynamic bounding-box dimensions (`m`, `cm`, `mm`, `in`), and isolated debug render passes (Albedo, Normal, Roughness, Metalness, AO, Emissive, and Wireframe).

Two rendering invariants keep interaction smooth at 60 Hz across complex multi-material meshes:

- **Single WebGL Context**: Exactly one `<Canvas>` exists across the entire application; its `frameloop` is gated on the active view so state survives navigation without background GPU churn, while secondary previews copy frames via `viewportBridge` (`preserveDrawingBuffer: true`).
- **Zero-Recompile Material Uniforms**: `pbrController` mutates `THREE.MeshPhysicalMaterial` instances directly outside React's render cycle. Scalar sliders (`roughness`, `metalness`, `normalScale`, `ior`) never raise `needsUpdate`, whereas `0 ↔ >0` facility-factor crossings (`clearcoat`, `sheen`, `transmission`) trigger controlled shader recompilation only when required.
- **Live Asset Reload**: `chokidar` watches the active `.glb` on disk and refreshes geometry on save, paired with `CommandManager` transactions for multi-step undo/redo across 12 PBR map slots and multi-material mesh targeting.

## Asset Library, Texture Packing & AR Export

Mirage treats local 3D assets as structured entries (`entry.json` + copied binary assets) across six top-level views: **Hub**, **Workbench**, **Model Library**, **Entry Detail**, **Settings**, and **Agent Studio**.

- **Native Texture & Thumbnail Engine**: An in-process `@janhapke/sharp-electron` service generates `.webp` thumbnails on Node's libuv threadpool (`~3–5 ms` with deduplicated in-flight requests and a 4-task concurrency cap), while heavy ORM channel packing (`R=AO, G=Roughness, B=Metalness`), normal Y-flips, and roughness inversions run in a dedicated worker (`texturePacker.ts`) with an HTML5 Canvas fallback (`canvasOrmPacker.ts`).
- **Production Export & Audits**: The Export Studio pairs a **Performance & Geometry Audit** (polygon budgets, mesh draw calls, `.glb` size thresholds) with transparent WebP/PNG poster capture, standalone `.glb` and Apple Quick Look `.usdz` baking, and complete Web/AR `.zip` bundles.

## Design System & Swappable Theme Engine

Every interface surface follows the **Mirage Operations Design System**: `0px–2px` architectural radii, `1px` hairline borders instead of decorative drop shadows, `Instrument Sans` paired with tabular `JetBrains Mono` metrology, and **29+ reusable UI primitives**—all enforced automatically by `designSystemCompliance.test.ts`.

## Security Model & Experimental Agent Studio

Because the renderer parses untrusted binary models (`.glb`, `.gltf`, `.hdr`, `.webp`) and relays external LLM responses, Electron's main process treats the renderer as an untrusted caller across a strict IPC boundary:

- **Sandboxed Renderer & Typed Preload**: `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, production Content-Security-Policy, and a flat 51-method `window.electronAPI` bridge with zero shared business logic.
- **Root-Confined Access Policy**: Every file operation and `local-asset://` stream passes through `accessPolicy.ts` (`fs.realpath` symlink resolution + `path.relative` containment), Zod payload schemas on all 49 IPC channels (with prototype-pollution key rejection), and atomic `safeStorage` credential encryption in `vault.ts`.
- **Per-View Error Containment**: Separate React error boundaries isolate each top-level view and modal, backed by modular domain Zustand stores (`modelStore`, `pbrMaterialStore`, `variantStore`, `viewportStore`, `appStore`, `agentStore`) coordinated via `workbenchActions.ts`.
